# 一个服务一个 schema，禁止跨 schema 查询

8 个进程共用一台 MySQL 实例，但每个服务拥有独立 database，各自的连接账号只被授予自己 schema 的权限。共享实例是为了省内存与运维成本，schema 隔离是为了守住"聚合只有一个所有者"这条边界。共用 schema 是分布式单体最常见的成因——一旦允许 `JOIN`，服务拆分就只剩下进程隔离了。

## Considered Options

- **共用 schema + 表名前缀**：开发期省事，但半年后必然出现跨域 `JOIN`，到那时拆分成本远高于现在。
- **每服务独立数据库实例**：在本容量下纯属浪费内存，且备份成本翻倍。

## Consequences

- 跨域查询只能通过接口或事件。开发期会出现"我只需要 join 一下"的强烈诱惑，正确解法是加冗余字段或建投影表，而不是去拿权限。
- 库权限必须在建库脚本里就配置死，靠自觉是守不住的。
- 跨服务事务一律不存在，只有本地事务 + 事件（见 ADR 0004）。
