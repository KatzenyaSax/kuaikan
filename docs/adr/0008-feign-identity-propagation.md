# 服务间身份用转发传播，且只存在于用户触发的同步链路

网关认证后向下游注入 `X-User-Id` / `X-User-Roles` / `X-Internal-Timestamp` / `X-Internal-Signature`。
当服务再通过 Feign 调用其他服务时，用 `RequestInterceptor` 把这四个头**原样转抄**出去。

不转抄的后果不是报错，而是**静默的错误结果**：Feign 发起的是全新请求（按方法签名重拼 URL/method/body），入站 header 全部丢失，下游把请求当成匿名——用户明明赞过，页面显示未赞，且日志里什么都看不出来。

## 为什么是转抄而不是重签

重签（下游用共享密钥重新签发身份头）意味着**任何持有密钥的服务都能凭空造出任意身份**，等于把 ADR 0003 里内部签名建立起来的边界拆掉一半。转抄的语义是"我在替这个用户办事"，重签的语义是"我认为当前应该是这个用户"——后者是权限提升。

## 这条规矩只覆盖同步链路

| 场景 | 带身份吗 |
|---|---|
| 用户请求触发、链路内的同步调用 | ✅ 转抄 |
| RocketMQ 消费者 | ❌ 系统行为，没有"当前用户" |
| XXL-Job 定时任务 | ❌ 同上 |

实现上靠 `RequestContextHolder.getRequestAttributes()` 区分：非用户请求触发时它为 null，拦截器直接不传播。
MQ 消费者需要用户上下文时必须从**消息体**里取 actorId，不能指望 header。

## Consequences

- 四个头必须成套转抄，缺一个就整个放弃传播。发半套头会被下游当成"签名不匹配"而拒绝，那比不发更难排查。
- 签名自带的时间戳会随转抄一起走，60 秒窗口对"请求处理初期发起的 Feign 调用"绰绰有余。若将来出现长链路，需要重新评估窗口或改用不带时效的内部凭证。
- 所有 servlet 服务都必须依赖 `kuaikan-common-web`。**漏引依赖是完全静默的**：服务照常启动、照常返回 200，只是 `UserContext.userId()` 永远为 null、Feign 也不转发身份。P1 期间就踩过一次（只有 user-service 引了），靠 `/ping/whoami` 这个可观测端点才发现。
